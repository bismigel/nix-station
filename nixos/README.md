# labanos — NixOS host runbook

Everything here is declarative except the two files under `/etc/nixos-secrets`.
System config: `labanos.nix`. Disk layout: `disko-labanos.nix`.

## Hardware

Framework Laptop 16, AMD Ryzen 7040 (Radeon 780M), ALC295 codec, BAT1, NVMe
`/dev/nvme0n1`, internal "Laptop Camera" UVC device, WiFi/BT combo card.

## Disk layout

```
/dev/nvme0n1
├─ p1 (1G, ESP)     → /boot   (vfat, unencrypted)
└─ p2 (rest, LUKS2) → cryptroot
     └─ LVM VG pool
        ├─ swap (16G)  → [swap], resumeDevice   (hibernation; > RAM)
        └─ root (rest) → btrfs
            ├─ @     → /
            ├─ @nix  → /nix
            └─ @home → /home
```

TRIM is allowed through LUKS (`initrd.luks.devices.cryptroot.allowDiscards`), and
`resume=/dev/pool/swap` is generated by disko. Hibernation needs swap ≥ RAM:
16 G vs 13 GiB here.

## Install

1. Boot the NixOS installer on the target, with network.
2. From another machine (the one holding the LUKS passphrase):

   ```sh
   printf '%s' "$LUKS_PASSPHRASE" > /tmp/cryptroot.key
   nixos-anywhere --flake .#labanos \
     --disk-encryption-keys /tmp/cryptroot.key /tmp/cryptroot.key \
     --target-host root@<installer-ip>
   rm -f /tmp/cryptroot.key
   ```

   `disko-labanos.nix` reads the passphrase from `/tmp/cryptroot.key` on the
   installer (`passwordFile`). This is the only non-interactive install path;
   adjust if you install by hand.

3. **Before the first boot**, provide the secrets below over SSH to the
   installer, or the system comes up without a password or WiFi key (it still
   boots; activation only warns).

## Secrets: `/etc/nixos-secrets`

Deliberately **not** in git and **not** in the Nix store (a store path is
world-readable). `/etc` is not tmpfs on this host, so the files survive
rebuilds. Create the directory once with mode `0700`:

```sh
sudo install -d -m 0700 /etc/nixos-secrets

# WiFi PSK for "Potato Corner" - read at activation by nm-file-secret-agent
# because the profile is declared with psk-flags=1 (agent-owned).
sudo sh -c 'umask 077; bw get password "Potato Corner WiFi" --raw \
  > /etc/nixos-secrets/potato-corner.psk'

# Password hash for the labanos user (locked out otherwise).
# `openssl passwd -6` works too; a throwaway VM cannot check it for you.
sudo sh -c 'umask 077; nix run nixpkgs#mkpasswd -- -m sha-512 \
  > /etc/nixos-secrets/labanos.hash'
```

`system.activationScripts.nixosSecretsWarning` prints a warning on every switch
when either file is missing or empty — a switch never fails on their absence,
because both can be repaired afterwards (`passwd`, `nmcli`).

The LUKS passphrase is the third secret, held only in the password manager and
in your head; it is never written by this repo.

## Rebuild / rollback

```sh
sudo nixos-rebuild switch --flake ~/nix-station#labanos
sudo nixos-rebuild boot   --flake ~/nix-station#labanos   # no live switch
```

Retention is count-based: the weekly `nix-gc` service keeps the **5** newest
generations of the system profile, the embedded Home Manager profile, and (by
age) `nix profile` generations, then runs `nix-collect-garbage`. The boot menu
shows the same 5 (`systemd-boot.configurationLimit`).

## Deliberate choices

| Choice | Why |
| --- | --- |
| `services.openssh.enable = false` | Nothing may SSH into this laptop; tcp/22 is closed by the firewall as a side effect. The ssh client is still installed for git remotes. |
| `snd_hda_intel.power_save=0` | The ALC295 clips the first ~200 ms and pops after autosuspend. Costs ~0.5 W. |
| PipeWire quantum 1024, resample-quality 10 | This codec crackles at lower quanta under load; music is the common case. |
| `ConditionACPower` on the `swayidle-*-on-{ac,battery}` and `hibernate-on-battery` units | Idle locking, blanking and hibernation are power-source dependent, and systemd evaluates the condition itself, so no shell dispatcher decides anything. On AC the session locks after 2 h and never hibernates. |
| Lid: `suspend-then-hibernate` on battery, `suspend` on AC | The panel only offers s2idle (no S3), so a shut lid would keep draining; it hibernates after `HibernateDelaySec` (1 h) but resumes instantly within that window. On AC it never hibernates. |
| ly + PAM gnome-keyring rules | Proton VPN needs `org.freedesktop.secrets`; ly has its own PAM stack, so the keyring rules are mirrored into it. |
| Brave managed policies | Debloat: Rewards/Wallet/VPN/News/Talk/Leo/Tor/P3A off. Costs the "managed by your organization" label. |
| RS3 via pinned nixpkgs-23.11 | The native RS3 client links EOL OpenSSL 1.1. The pin is used **only** for `openssl_1_1`; the launcher wrapper puts it on `LD_LIBRARY_PATH` for the client only. Accepted risk — remove `nixpkgs-old`, `boltLauncher` and the two `problems.handlers` entries in `modules/base.nix` to drop it. |

## Wireless note

The AP publishes a 6 GHz BSSID for the same SSID that always fails WPA-PSK
auth; wpa_supplicant reconsiders it every 1800 s and tore down the working 5 GHz
link each time. The profile is therefore pinned to `band = "a"`. DNS: Cloudflare
is listed first via `ipv4.dns-priority = "0"`, DHCP DNS stays as fallback so
`*.home` names still resolve through the router.
